# Sipon 全应用磨砂质感升级方案

日期：2026-10-13  
状态：设计与实施提案；尚未实施界面改造。  
设计方向：细腻磨砂、柔和光感、清晰层次、克制品牌色。

## 1. 目标与范围

在现有 Flutter 应用和品牌视觉上，建立一套贯穿首页、地图、动态、个人中心及详情、表单的材质规范。用户应感受到浮层轻盈通透、内容清楚易读、布局有节奏、操作反馈细腻。

现有底栏已经具备合适的磨砂效果，作为样式基准保留。优先解决其他区域与底栏的协调性，不把重做底栏列为本轮主要工作。

本轮采用 Flutter 背景模糊和自绘装饰实现。交付目标是高品质磨砂质感，不包含背景折射、液体融合、动态色散、原生 Liquid Glass 接入，也不需要新增图形效果依赖。保留 MaterialApp、业务逻辑、导航结构、现有账号与地图能力。

三端共享 Sipon 的颜色、圆角和材质语言；安全区、返回手势、键盘、系统权限与原生地图继续按平台适配。Android 也纳入质感升级，不单独保留另一套默认 Material 外观。

仓库已有 `ui_adaptive_glass_plan.md`，其中包含按平台更换底栏、原生液态玻璃和平台能力扩展等建议。本方案依据本次需求重新收敛范围，实施本轮时采用本方案；旧文保留参考，不合并执行其中的功能扩展。

## 3. 页面层次与材质规则

按背景、内容、悬浮控制、模态操作四个层级组织界面。

| 层级 | 视觉表达 | 典型区域 |
| --- | --- | --- |
| 页面背景 | 安静、微暖的底色；局部极弱渐变 | 首页、个人页、普通列表 |
| 内容表面 | 清晰实色或近实色，弱边缘，少量阴影 | 酒吧卡片、动态、预算、配方、设置列表 |
| 悬浮控制 | 可透出背景色彩的磨砂，小面积高光 | 底栏、图片上的返回按钮、地图工具 |
| 模态操作 | 更厚的磨砂或实色，配合遮罩 | 加号菜单、筛选、城市选择、短操作面板 |

真实模糊用于背后确实有内容经过的区域。在纯色背景上的静态搜索框可以使用实色或浅色表面；只有悬浮在滚动内容上时才启用模糊。避免为了表现玻璃而额外堆放彩色光斑。

同一组件只保留一个明确的材质外壳：面板整体磨砂，内部操作项用弱实色；输入框内部透明，避免形成重复边框和嵌套色块。Apple 对导航与内容层的区分也提供了参考，但本方案不声明复刻其系统材质。[Apple 材质指南](https://developer.apple.com/design/human-interface-guidelines/materials)

## 4. 磨砂材质配方

以下为首轮试制值，属于 Sipon 设计建议，不是平台标准或性能保证。以现有底栏和加号面板为参考校准后再冻结。

### 4.1 三档材质

表中的百分比均表示底色不透明度，数值越大越不透；sigma 表示 Flutter 模糊参数，不等同于其他设计软件的模糊半径。

| 配方 | 使用场景 | sigma 建议 | 浅色底色不透明度 | 深色底色不透明度 |
| --- | --- | --- | --- | --- |
| 轻磨砂 | 图片上的小按钮、少量辅助控件 | 12–16 | 68%–78% | 62%–76% |
| 标准磨砂 | 搜索浮层、悬浮工具、导航类容器 | 18–22 | 74%–84% | 70%–84% |
| 厚磨砂 | 短菜单、筛选和城市选择面板 | 18–24 | 84%–92% | 84%–94% |

现有底栏使用自己的渐变配方，等效迁移时保留原值，不强制套入表中区间。现有加号面板 76% 不透明度也作为对照样本保留，只有出现可读性或层级问题时才调整。

厚磨砂主要通过提高底色遮蔽程度实现，不靠无限增加模糊。表单和长列表优先使用实色表面。

### 4.2 边缘、光感与投影

- 边缘宽度初始为 0.5–1 个逻辑像素，按设备像素比检查清晰度。
- 浅色材质使用偏白的柔和边缘，顶部略亮；深色使用低不透明度亮边，避免显眼的白框。
- 光照方向统一从左上方进入，静态亮度变化要弱，文字区域保持稳定。
- 悬浮容器初始投影：垂直偏移 4–8、模糊 16–24、黑色不透明度 6%–10%；深色模式主要依赖表面亮度和边缘区分层次。
- 内容卡片优先选弱描边或轻阴影之一，避免描边、外阴影、内阴影同时堆叠。
- 首版不添加噪点纹理、持续扫光、跟随手指的高光或泛光，减少视觉干扰和额外绘制。

### 4.3 颜色

保留当前主题中的成熟色值作为起点：浅色页面 #FBF8F9、内容表面 #FFFFFF、主文字 #252229；深色页面 #151216、基础表面 #211C22、抬高表面 #2C252D、主文字 #F5EFF4。

品牌色 #9A3D78 用于主要操作、选中项和少量强调。深色沿用现有浅品牌色 #E8A0CC。品牌弱底用于标签和辅助入口，避免让每一层都呈粉紫色。成功、警告、错误、评分继续读取既有语义色，不统一染成品牌色。

玻璃的底色、高光、描边与阴影分别定义，避免一个透明度值同时控制所有元素。

## 5. 排版、形状和控件规范

| 项目 | 建议规范 |
| --- | --- |
| 页面标题 | 24–28，字重 600–700；不强制每页都使用大标题 |
| 分区标题 | 18–20，字重 600 |
| 正文与操作文字 | 15–16，字重 400–500 |
| 辅助说明 | 12–13；重要信息不使用低对比度细字 |
| 中文正文行高 | 约 1.45–1.6，按实际字体调校 |
| 间距尺度 | 4、8、12、16、20、24、32 |
| 页面水平留白 | 通常 20–24；首页现有 23 可保留，不为统一数字改坏布局 |
| 卡片内边距 | 16–20 |
| 内容卡片圆角 | 18–22 |
| 输入框与普通按钮圆角 | 14–18；悬浮搜索和导航使用胶囊 |
| 面板圆角 | 24–28；保留现有加号面板 28 |
| 点击区域 | 以至少 48×48 逻辑像素为设计目标，图形可小于热区 |

字体优先使用系统字体回退，现有品牌字体仅用于明确的品牌位置。无需为本轮新增全局字体包。中英文、大字号、长城市名与长酒名均需验收。

主按钮使用品牌实色和清楚文字；次按钮使用弱表面或描边；只有覆盖图片或地图的工具按钮使用磨砂。输入框必须区分正常、聚焦、错误、禁用状态；选择状态通过形状、图标或文字共同表达。

## 6. 各页面改造方案

### 6.1 首页：建立全局样板

保留当前信息顺序、入口和内容宽度。顶部品牌与城市区域保持简洁，搜索控件统一高度、图标尺寸与圆角。收起时采用轻表面；展开后使用标准磨砂容器，建议列表提高底色不透明度，避免背景文字穿透。

保留搜索展开时底栏隐藏、键盘避让、关闭后恢复的逻辑。已有全屏背景模糊只作为搜索模态状态使用，退出后移除，不作为常驻装饰。

鸡尾酒和酒吧推荐统一图片比例、裁剪、标题基线和标签间距。卡片使用清晰内容表面，靠图片和留白体现品质。统一图片加载占位、空数据与失败重试的视觉，避免加载前后布局跳动。

首页样板交付：浅色/深色默认态、滚动态、搜索展开、键盘打开、加载与空数据截图。

### 6.2 地图：控制层磨砂，信息层稳定

地图搜索与筛选、定位工具使用同一套标准磨砂配方；相邻小按钮优先共用一个容器，减少独立滤镜。选中状态使用品牌色或明显图标变化。

地点摘要面板可以使用厚磨砂，展开为长内容详情后切换为稳定的近实色或实色表面。照片、营业状态、地址和路线信息保持高可读性。面板拖动时固定模糊强度，避免每一帧改变 sigma。

MapKit、Android 地图和项目实际使用的鸿蒙地图分别验证：标准底图、卫星图、深色底图、缩放、拖动、地点切换、面板展开。原生地图的合成能力不能从 Flutter 内容页面推断。

若当前平台无法正确模糊原生地图，使用不透明的主题表面、弱亮边与轻阴影回退，保证文字与操作可靠。平台能力通过集中策略表达，不在每个按钮内分散判断。

### 6.3 动态：突出内容，减少装饰

动态文字和图片用稳定背景。统一头像、昵称、时间、正文、图片和操作区的间距；点赞、评论等反馈使用短促颜色和缩放变化，不在每条动态上加背景模糊。

评论浮层和分享短菜单使用厚磨砂；评论长列表区域使用近实色内容面。首页复用的动态区域与独立动态页使用相同内容组件规范。

### 6.4 个人中心：柔和背景与清晰分组

头像和昵称区可以保留轻微品牌渐变，降低大面积渐变对内容的干扰。快捷入口统一图标尺寸、字重和触控范围；预算、账单、统计采用实色卡片，通过分组与数字层级建立秩序。

设置、通知、语言、编辑资料等页面采用统一的分组列表和标题规范。危险操作保留错误语义色，辅助说明不能因追求浅淡而难读。

### 6.5 酒吧与鸡尾酒详情：图片上的玻璃，正文里的留白

大图上的返回、收藏或更多按钮使用轻磨砂；如当前页面存在固定顶部栏，仅在图片或正文滚过其下方时呈现标准磨砂。必要时在图片边缘补充局部遮蔽，提高控件对比度。

标题、评分、地址、配方、介绍和评论使用清晰内容表面。统一分区间距和标签，避免每个段落套一个不同阴影和圆角的盒子。长文字和配方表格不使用透明背景。

### 6.6 表单、记录与路线

登录、打卡、评论编辑、添加酒吧、资料编辑、饮酒记录和路线编辑优先保证输入稳定。输入区域采用实色，错误提示就近展示；底部固定操作区在确有内容滚过时可使用标准磨砂，并为键盘和内容预留空间。

日期选择、确认弹窗和短选项面板统一外壳与按钮规范；保留现有正确的平台交互和数据行为，不为外观替换登录或定位方案。

### 6.7 全局弹层与提示

加号面板作为现有参照，统一内部入口的图标容器、标题字重、内边距和按压状态。城市、筛选和短操作面板共用表面规范。

破坏性确认与长说明弹窗采用厚实表面。成功、错误、离线等提示沿用现有消息入口，统一圆角和语义图标，无需把短暂提示强行做成高透明玻璃。

## 7. 动效规范

| 交互 | 建议反馈 | 起始时长 |
| --- | --- | --- |
| 小按钮按下 | 缩放至 0.97–0.98，轻微底色变化 | 90–130ms |
| 松手恢复 | 平滑恢复，少量回弹仅用于适合的控件 | 160–220ms |
| 菜单出现 | 淡入和短距离上移 | 220–280ms |
| 菜单关闭 | 淡出和原路返回 | 160–220ms |
| 搜索展开 | 保留现有状态联动，连续改变容器布局 | 220–300ms |
| 主题变化 | 材质颜色平滑过渡，模糊强度尽量固定 | 跟随现有主题动画 |

底栏现有滑动和跳转反馈保持原行为。页面转场与滚动物理不在首批全局替换。手指拖动的面板必须跟手，不叠加延迟动画。

降低动态效果时移除装饰性缩放、位移和回弹；需要表达状态变化时保留简短反馈。接入时核对实际 Flutter SDK 的无障碍映射：当前官方文档区分 disableAnimations 与 iOS reduceMotion，不能只读一个标记就宣称所有平台已覆盖。[Flutter 动效设置](https://api.flutter.dev/flutter/widgets/MediaQueryData/disableAnimations.html)

## 8. Flutter 落地架构

沿用 `lib/app/theme/` 和 `lib/shared/widgets/`，不新增与它们职责重复的庞大平台设计层。

| 文件或组件 | 职责 |
| --- | --- |
| 现有 sipon_theme.dart | 统一文本、输入、卡片、对话框、按钮与面板主题 |
| 现有 sipon_theme_colors.dart | 保留颜色语义，必要时补充高光和边缘色 |
| 拟新增 sipon_material_theme.dart | ThemeExtension，承载三档材质、圆角、边缘、阴影和动效参数 |
| 拟新增 sipon_glass_surface.dart | 只负责材质绘制，支持明确的实色回退 |
| 拟新增 sipon_surface.dart | 普通内容表面，避免业务卡片重复装饰代码 |
| 拟新增 sipon_glass_icon_button.dart | 统一图片和地图工具按钮的材质、语义、焦点和触控范围 |
| 拟新增 sipon_sheet_surface.dart | 统一面板外壳、安全区与内容布局约定，不取代业务逻辑 |

所有新名称均为拟议接口，实施时结合现有复用组件调整。

材质组件提供配方、圆角、child、模糊启用状态和实色回退能力。首批避免暴露大量随意调色参数；确有例外时使用具名配方，防止页面重新散落魔法数字。

渲染顺序：外部阴影 → 圆角裁剪 → 背景模糊 → 半透明底色 → 轻高光与边缘 → 内容。阴影放在裁剪外，内容的文字和图标不参与背景模糊。优先通过材质底色控制不透明度，避免在整个子树外包 Opacity 导致文字一起变淡和额外合成问题。

全局 ThemeExtension 注入时保留现有 SiponThemeColors；实现 copyWith 和 lerp，使主题切换连续。先制作独立预览，再把底栏已有绘制抽到公共组件，逐项核对迁移前后截图。

## 9. 性能、可访问性与回退

### 9.1 绘制约束

真实模糊按实际轮廓裁剪；普通列表项不逐个增加 BackdropFilter。首页默认态尽量维持现有底栏的滤镜规模，有覆盖内容的顶层控件时才新增滤镜。滤镜数量只是审查信号，不能替代面积、重叠和原生合成的性能测量。

避免模糊容器嵌套；短面板内的卡片不再模糊一次。多个不重叠滤镜可在 SDK 支持且截图验证正确时评估共享 BackdropGroup；重叠滤镜不能简单共用同一 backdrop key。仅模糊单张图片时使用 ImageFiltered。以上边界依据 [Flutter BackdropFilter 文档](https://api.flutter.dev/flutter/widgets/BackdropFilter-class.html)。

不把 RepaintBoundary 视为免费缓存背景模糊的方案；只有重绘诊断表明确有收益时才添加。滚动偏移只更新局部顶栏，不驱动整页重建。关闭搜索和弹层后移除不可见滤镜与动画。

### 9.2 回退规则

支持标准磨砂与实色两档实现，布局、文字、触控区域和状态完全一致。原生视图不支持、辅助设置要求更清晰或设备验证不通过时使用实色。

首版以已验证的平台/场景能力决定回退，不凭设备价格或机型名称推断 GPU 性能，不承诺未经实现的自动性能识别。保留开发预览强制回退开关；是否向普通用户提供设置项，留待实际需求决定。

### 9.3 可读性与无障碍

项目验收目标：普通文字与最终合成背景对比度至少 4.5:1；关键图标及控件边界以 3:1 为目标。测试必须覆盖亮白、近黑、彩色图片、文字背景和卫星地图，不能只比较半透明底色的名义色值。无法稳定保证时提高底色不透明度或直接使用实色。

响应 highContrast，提高遮蔽和边界清晰度；当前 SDK 提供的系统信号以实际验证为准。[Flutter 高对比度设置](https://api.flutter.dev/flutter/widgets/MediaQueryData/highContrast.html)

降低透明度与降低动态是不同设置。实施时核实引擎是否暴露降低透明度；若没有，则通过适配层读取支持平台的系统设置，避免把 disableAnimations 当成降低透明度。所有图标按钮具备可读标签，操作顺序适合屏幕阅读器，大字模式不截断主要操作。

## 10. 实施阶段与交付

以下为单名开发者在具备构建环境和真机的情况下的粗略工作量估计，不是交付承诺；以页面数量和基线验证结果重新排期。

| 阶段 | 任务 | 交付与通过条件 | 估算 |
| --- | --- | --- | --- |
| 0：基线 | 收集现有页面截图、平台/引擎版本、目标设备与关键交互性能 | 有可重复的改造前对照；确认地图能力 | 0.5–1 天 |
| 1：规范与组件 | 三档材质、实色表面、按钮/面板外壳、预览与回退 | 浅深色和复杂背景均清晰；底栏可等效复用 | 1–2 天 |
| 2：首页样板 | 搜索、内容卡片、加号面板内部、图片状态 | 首页全状态视觉确定，交互无回归 | 1.5–2.5 天 |
| 3：主要页面 | 地图、动态、个人中心、酒吧和酒款详情 | 统一材质并完成地图回退验证 | 2.5–4 天 |
| 4：深层页面 | 表单、记录、路线、设置、消息和通用弹层 | 主题与状态完整，主要任务流程通过 | 2–3 天 |
| 5：验收 | 三端真机、无障碍、性能、修复 | 验收矩阵完成并记录剩余限制 | 1.5–2.5 天 |

预计合计约 9–15.5 人日；原生地图兼容或既有深色缺口可能增加工作量。按阶段保留可独立审查与回退的变更，不一次性机械替换全项目。

优先级：首页搜索和卡片、通用面板为 P0；地图、个人中心和主要详情为 P1；其余深层页面为 P2。底栏仅在公共组件迁移或实际问题需要时变更。

## 11. 验收矩阵

| 维度 | 检查场景 | 通过标准 |
| --- | --- | --- |
| 材质 | 纯色、图片、密集文字、地图之上 | 层次自然，文字稳定，无重复模糊或裁剪漏出 |
| 主题 | 浅色、深色、跟随系统、弹层打开时切换 | 无白闪、残留固定色，表单与滚动状态保留 |
| 交互 | 搜索开关、键盘、底栏、弹层、地图拖动 | 无穿透点击、手势拦截、遮挡或关闭后残余滤镜 |
| 布局 | 小屏、大屏、中英文、长文本、系统大字号 | 关键内容可达，按钮可点，无溢出 |
| 内容状态 | 图片加载/失败、空列表、离线、错误、禁用 | 视觉统一，原因和下一步清楚 |
| 无障碍 | 高对比度、降低动态、降低透明度、屏幕阅读器 | 回退生效，操作语义清晰，不依赖透明度表达状态 |
| 平台 | 实际发布的 iOS、Android、鸿蒙构建 | 每个平台有独立记录；未测项明确标为待验收 |
| 底栏回归 | 各标签、加号、安全区、键盘、地图面板联动 | 与基线保持一致，除非有明确记录的设计修正 |

性能使用真机 profile 构建测量，发布构建确认观感；不以 debug 模式帧率验收。每个目标设备固定执行首页连续滚动、搜索开关、地图拖缩、面板展开关闭，记录相同场景改造前后各三次约 30 秒的结果。

建议目标：在选定的 60Hz 验收设备上，稳定交互阶段 UI 和 raster 帧耗时各自 p95 尽量不超过 16.7ms；若要求以 120Hz 运行，目标对应为 8.3ms。另记录超预算帧比例及原生地图合成情况，不能只凭 Flutter 单一指标判定整屏流畅。基线已不达标时说明原有问题，并通过减小区域、减少叠层或实色回退避免新增明显退化。

自动化检查聚焦真实风险：材质回退策略、搜索/底栏联动、面板关闭与主题切换状态；复用已有页面测试。视觉快照固定字体与尺寸用于对照，不能替代原生地图和真实 GPU 效果验证。实施批次完成后运行相关测试与静态检查；本方案文档本身不代表上述验证已通过。

## 12. 交付清单与完成定义

- 一套冻结的浅色/深色材质参数及预览，包含复杂背景与实色回退对照。
- 可复用的材质、内容表面、悬浮按钮和面板外壳，页面按规范接入。
- 首页、地图、动态、个人中心、详情及关键输入页面的改造前后截图。
- 按平台记录的视觉、交互、可访问性和性能验收结果。
- 每批修改范围、回退方式、未解决问题及适用场景。

完成标准是：底栏与其余界面视觉协调，内容清晰，浮层有细腻磨砂层次，深浅色与复杂背景都可靠，原生地图和普通页面均有经过验证的实现或回退。仅给部分控件添加模糊、只完成浅色截图或只通过模拟器检查，均不构成本轮完整交付。
